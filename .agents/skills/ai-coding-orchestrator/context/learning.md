# Learning and Self-Improvement Pack

Load only for learning or orchestration self-improvement.

`Observe -> Outcome -> Candidate -> Regression -> Safety -> Shadow/Canary -> Promote -> Monitor -> Rollback`.

Candidate executable changes are never active because a model proposed them. Require content-addressed versioning, baseline comparison, deterministic regression replay, safety gates, promotion evidence and rollback lineage.

Prefer repeated evidence over one-off wins. Measure improvement against a known baseline while preserving protected behavior and verification quality. Never let learned behavior silently expand credentials, permissions or security boundaries.

Keep `CANDIDATE_ID | PARENT_DIGEST | SOURCE_DIGEST | REGRESSION | SAFETY | PROMOTION | ACTIVE_VERSION | ROLLBACK_TARGET`.
