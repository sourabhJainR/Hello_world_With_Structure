# Capability: Proof of Concept

Build the smallest practical experiment needed to answer a technical question or reduce a major implementation risk.

Rules:

- Keep the scope intentionally narrow.
- Prefer isolated code under a clearly identifiable POC or temporary location.
- Do not present POC code as production-ready.
- Avoid unrelated cleanup or refactoring.
- Run only the checks needed to prove or disprove the hypothesis.

Return:

## Hypothesis
What is being tested.

## Experiment
What was built or configured.

## Evidence
Commands run, observed results, and limitations.

## Conclusion
Supported, rejected, or inconclusive.

## Production recommendation
Whether to proceed, change approach, or investigate further.
